## ドキュメント概要

この記録は、Cloudflare公式のChallenge Page判定と提出フォームの構造判定を追加した検証支援コードで、方式Cによる`V-03`を再実行した結果を保持します。実際のアカウント名、Cookie、Cookieの派生値、CSRFトークン、ソースコード、ソースコードのハッシュ、生のヘッダー、生のHTML、生ログは含めません。

空のセッションによる`GET /settings`はログインページへの302誘導となり、同じ時点の通常ブラウザから方式Cで取り込んだ`REVEL_SESSION`一つだけを付けた同じリクエストは200となりました。アカウント識別情報を1件取得し、非表示入力した期待値との一致を確認できたため、`V-02`の当日再確認は合格です。

続く提出ページのGETは200、`text/html`で、Cloudflare公式がChallenge Pageの識別子として示す`cf-mitigated: challenge`はありませんでした。したがって、この応答は前回のような本文中のTurnstile関連文字列だけではなく、公式ヘッダーに基づいて「Cloudflare Challenge Pageではない」と分類できました。

提出フォームは1件、POST方式、CSRF入力1件、対象問題の選択肢1件、ソースコード欄1件まで確認できました。一方、現在のパーサーが静的HTMLで送信対象として認識する`name="data.LanguageId"`付きの言語`select`は0件で、正規言語`python-cpython`の候補も0件でした。この値は、`name`がまだ付いていない言語`select`や選択肢まで存在しなかったことを示しません。このため、実行は`parsed_form.classification != "ready"`の分岐で`V-05`を不合格として停止しました。また、同じフォーム内にTurnstileウィジェット1件を観測したため、仮に言語を解決できても、次の`submission_ready`ゲートは通過しません。本実行では提出確認画面、提出POST、提出ID取得、判定確認へ進んでいません。

### 0.2. 今回停止した正確な分岐

実行が直接停止したのは、Cloudflare Challenge Page判定でも、Turnstileの`submission_ready`判定でもなく、フォーム解析直後の次の条件です。

```python
if parsed_form.get("classification") != "ready":
    result["v05"] = "fail"
    # V-05で言語を一意に解決できず停止
```

| 評価順 | 条件 | 本実行 | 判定 |
|---:|---|---|---|
| 1 | 認証済みHTMLを安全に読める | `authenticated_html_classification: ready` | 通過 |
| 2 | Cloudflare Challenge Pageではない | `cf_mitigated_class: absent` | 通過 |
| 3 | 提出フォームの必須構造と言語を一意に解決できる | `name="data.LanguageId"`付き言語`select`の認識件数0件、候補0件 | ここで`V-05: fail`として停止 |
| 4 | 対象フォームに能動的なTurnstile関連付けがない | 対象フォーム内ウィジェット1件 | 観測値は不通過だが、手順3で停止したため実行経路は未到達 |
| 5 | 人による提出承認 | 承認画面を表示していない | 未到達 |

この区別により、「CloudflareがBotと判定してチャレンジページへ置換したため停止した」とは解釈しません。今回の200応答はCloudflare公式ヘッダー上のChallenge Pageではなく、AtCoderの提出フォーム構造を含むHTMLでした。

### 8.1. 実行後調査による言語選択欄の解釈

`p0-06`確定後、認証情報を使わずにAtCoderの公開ページと、そのページが読み込む[AtCoder公式`contest.js`](https://img.atcoder.jp/public/cd2aee3/js/contest.js)を確認しました。[AtCoder公式の提出案内](https://atcoder.jp/contests/APG4bPython/tasks/APG4bPython_a?lang=ja)でも、利用者が表示名から言語を選んだ後に提出する操作が説明されています。

公式JavaScriptは、`#select-task`がある提出フォームについて次の順で問題別の言語選択欄を切り替えます。

1. `#select-lang`の`data-name`から送信用フィールド名を取得する。
2. `#select-lang`配下の全`select`から`name`、`required`、`current`を外す。
3. 選択中の問題に対応する`#select-lang-<problem-id>`だけを表示する。
4. その配下の`select`へ送信用の`name`、`required`、`current`を付ける。
5. 選択された`option`の値を、通常のHTMLフォーム送信対象にする。

[HTML標準](https://html.spec.whatwg.org/dev/forms.html)では、フォームコントロールの`name`が送信時のデータ名になります。AtCoderの現在の構造と検証支援コードを合わせると、提出本文は概念上、次の名前と値を含みます。値は説明用のプレースホルダーであり、本実行の秘密値または実値ではありません。

```text
data.TaskScreenName=<problem-id>
data.LanguageId=<AtCoder固有の言語ID>
sourceCode=<source>
csrf_token=<token>
```

したがって、`p0-06`の`language_select_count: 0`は「言語選択欄がHTML内に存在しなかった」ことではなく、「現在のパーサーが、静的HTMLの時点で`name="data.LanguageId"`を持つ`select`を認識できなかった」ことを表します。JavaScript実行前の問題別`select`は存在したが、まだ`name`を持っていなかった可能性があります。

ただし、本実行の匿名化射影は、`name`がない`select`、`#select-lang`の`data-name`、問題別コンテナ、全言語選択肢の件数を保持していません。そのため、この説明は公式JavaScriptと観測結果を合わせた有力な推論であり、`p0-06`のHTMLについて直接確定した事実ではありません。`V-05`を遡及して合格へ変更しません。

### 8.2. 次の安全な修正・再検証方針

同じ検証支援コードで`V-03`を直ちに繰り返さず、まず外部作用のない`V-05`の修正と読み取り専用再検証を行います。

1. 対象提出フォーム内の`#select-task`を一意に取得し、対象問題`abc300_a`が1件だけ存在することを確認する。
2. `#select-lang`が1件だけあり、その`data-name`が期待する`data.LanguageId`であることを確認する。
3. `#select-lang-abc300_a`を1件だけ取得し、配下の言語`select`を、初期状態の`name`有無に依存せず一意に特定する。
4. その`option`だけからCPython候補を抽出し、AtCoder固有ID、表示名、処理系、バージョンを1件へ解決する。0件または複数件なら停止する。
5. 公式JavaScriptの実行前構造を模したローカルfixtureに加え、コンテナ欠損、重複、`data-name`不一致、候補0件・複数件の拒否テストを追加する。
6. 変更後はPOSTを無効にした読み取り専用実行で、名前なし`select`の件数、対象問題用`select`の件数、候補数、解決結果だけを匿名化して確認する。生HTML、全選択肢、Cookie、CSRFトークンは保存しない。

この修正で`V-05`に合格しても、`V-03`の提出許可には直結させません。対象フォーム内のTurnstileウィジェットという独立した停止条件を解除せず、素のHTTPクライアントによるPOST、自動的なTurnstile操作、追加トークン取得は行いません。次に提出経路を検討する場合は、方式Aの可視専用ブラウザで人が操作する範囲を設計レビューし、MVPの信頼境界を超える場合は回避実装をせず範囲と価値仮説を再決定します。

本結果は「Cloudflare Challenge Page判定の修正が機能した」ことを示しますが、「方式Cの提出が成立した」ことは示しません。次は、言語IDの問題別解決を公式JavaScriptと同じ安全条件で実証してから、Turnstileを含む提出方式を別の判断として扱います。

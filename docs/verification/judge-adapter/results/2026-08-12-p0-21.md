## ドキュメント概要

`p0-20`で実装したV-03→V-04統合再検証を実行できるよう、AtCoderへの提出上限を「検証全体で合計1件」から「事前に明示承認した実サービス検証実行ごとに最大1件」へ変更した記録です。本変更は方針、文書、操作メッセージ、匿名化済み結果の上限メタデータだけを更新し、AtCoder、Cloudflare、Google Chromeへ接続していません。

## 0. 結論

| 判定対象 | 結果 | 根拠 |
|---|---|---|
| 提出上限の単位 | **変更** | 日単位または検証全体の累積上限ではなく、目的と対象を事前記録して明示承認した実サービス検証実行ごとに最大1件とする |
| 同一承認内の再提出 | **禁止を維持** | `SEND_STARTED`相当以降は成功・失敗・応答不明のいずれでも枠を消費し、自動再送と手動再提出を行わない |
| V-03→V-04統合再検証 | **新規提出最大1件を許可** | `abc300_a`、`python-cpython`、`atcoder_v04_integrated.py`を使う次の実サービス検証に限定する |
| `V-04` | 未合格（一部観測）を維持 | 本変更では実サービスの判定待ちと最終判定を観測していない |
| 外部作用 | **0件** | 方針変更とローカル確認だけで、GET、POST、ブラウザ起動、提出を行っていない |

この上限はAtCoder側の「1日1回」という制限を表すものではありません。日付が変わっても提出許可は自動的に増えず、同じ日に別の許可を暗黙に追加することもありません。

## 1. 変更した提出許可モデル

提出を伴う実サービス検証は、次を事前に固定した一つの承認単位として扱います。

1. 検証目的と対象の`V-*`項目
2. 終了済みの対象問題、言語、ソースの実行内別名
3. 使用する検証支援コード
4. 既存提出を再利用できない理由
5. 新規提出試行の上限。既定かつ最大は1件
6. 送信開始後は自動再送せず、応答不明でも同じ承認で再提出しないこと
7. 実行後に、0件の場合を含む提出試行数と結果を新しい実行記録へ残すこと

`SEND_STARTED`相当、ブラウザ経路では対象フォームの`submit`イベントへ到達した時点で1件の枠を消費します。AtCoderによる受理、拒否、通信障害、結果ページへ遷移しない状態を区別できなくても、同じ承認で再提出しません。送信前に安全側で停止した場合は枠を消費しませんが、停止理由の解消と実行条件の不変を確認してから再開します。

追加提出が必要になった場合は、日次リセットではなく、必要性と前回の状態を新しい記録へ明示した上で別の承認を行います。この方針により、実サービスの副作用を1回ごとにレビューできる状態を保ちつつ、過去の提出から復元できない判定待ち等を再検証できます。

## 2. 今回承認する統合再検証

| 項目 | 許可内容 |
|---|---|
| 目的 | V-03で新しい提出IDを取得し、その直後から同じIDのV-04判定待ちと最終判定を時刻付きで観測する |
| 対象問題 | 終了済み過去問`abc300_a` |
| 正規言語 | `python-cpython` |
| ソース | 本人が作成した`source-B`。本文とハッシュを成果物へ保存しない |
| 実行入口 | [`atcoder_v04_integrated.py`](../../../../scripts/verification/atcoder_v04_integrated.py) |
| 新規提出試行 | 最大1件 |
| 自動再送 | 0回 |
| 同一承認での再提出 | 0回。送信状態または結果が不明でも再提出しない |
| 既存提出を使わない理由 | `submission-A`は最終判定済みで、過去の判定待ちを後から復元できない |
| 結果の保存先 | 本変更とは別の、次の新しい実行記録 |

本記録はこの実行を許可するだけで、実行した証拠ではありません。利用者が統合スクリプトを対話ターミナルから開始し、画面上でこの1件を改めて確認した場合だけ提出へ進みます。

## 3. 維持する安全境界

- 対象は本人のアカウント、終了済み過去問1件、CPython 1言語に限定する。
- 通常ChromeでV-04方式Cセッションを提出前に準備し、別の空の専用ChromeでV-03を人が操作する。
- ログイン、Turnstile、承認句、AtCoder本体の提出ボタンは人が操作する。
- CDP、WebDriver、リモートデバッグ、ヘッドレス化、指紋偽装、Turnstile自動操作、提出クリック自動化を行わない。
- V-04は同じ提出ID1件だけを既存の有限ポーリング上限で観測する。
- Cookie、アカウント名、実際の提出ID、ソース本文、生応答を匿名化済み成果物へ保存しない。
- V-03またはV-04が失敗、不明、未完了でも自動再送または再提出しない。

- `submission_limit: 1`または`submission_post_limit: 1`、提出イベントの順序検査、送信前ガード、自動再送0回は変更していない。

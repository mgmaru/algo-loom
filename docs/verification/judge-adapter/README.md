>

>
> 正本: 検証項目、優先度、合格条件は[`JudgeAdapter`技術検証計画](../../project/judge-adapter-verification.md)を優先する

## ドキュメント概要

本書は、検証の入力を固定する方法、一時データと成果物の分離、外部作用前の停止条件、観測方法、成果物の確定手順を定義します。検証の合格条件やMVPの範囲は変更しません。

## 0. 結論

検証で扱うデータとコードを次の4領域へ分離します。

| 領域 | 置き場所 | 保持 | 内容 |
|---|---|---|---|
| 匿名化済み成果物 | [`results/`](results/) | Gitで保持 | 観測事実、合否、リクエスト集計、初期値候補、設計への反映先 |
| 再利用可能な検証支援コード | [`scripts/verification/`](../../../scripts/verification/) | Gitで保持 | 秘密情報と実行固有値を含まず、通信と外部作用の境界をレビューできるスクリプトとローカルテスト |
| 検証用作業データ | リポジトリ外の一時ディレクトリ | 検証後に破棄 | 仮想環境、実行固有の検証コード、入出力例、提出用ソースコード、一時出力 |
| 認証情報 | 方式Cではリポジトリ外の検証用一時領域、方式Aでは検証用secret store | 成果物へ移さず検証後に破棄 | Cookie、セッショントークン。パスワードは受け取らない |

`results/`へ生のコマンド出力を複製しません。必要な値だけを許可リスト方式で転記し、[記録テンプレート](results/run-record-template.md)の機密情報検査を通してから成果物を確定します。

## 1. 準備タスク

| ID | タスク | 依存 | 完了条件 |
|---|---|---|---|
| `T-01` | 検証入力を固定する | なし | 終了済み問題、1言語、1OS、期待するアカウント、提出用ソースコードを決める |
| `T-02` | 当日の外部条件を確認する | `T-01` | AtCoderの一般利用規約、対象コンテストの個別規則、Bot対策の状態を公式情報で確認する |
| `T-03` | 隔離した実行環境を作る | `T-01` | リポジトリ外に仮想環境、作業ディレクトリ、方式Cの一時Cookie領域を用意する |
| `T-04` | 観測方法を確認する | `T-03` | 本文・秘密情報を保存せず、時刻、所要時間、状態、欠損、リクエスト数を記録できる |
| `T-05` | 方式Cで読み取りだけの検証を行う | `T-02`〜`T-04` | `V-02`、`V-01`、`V-05`の順で確認し、提出前停止条件をすべて満たす |
| `T-06` | 1件の提出を承認する | `T-05` | 問題、アカウント、言語、ソースコードのハッシュ、外部作用を人が確認する |
| `T-07` | 提出と判定を確認する | `T-06` | `V-03`、`V-04`、`V-06`、`V-08`を同じ提出IDで確認する |
| `T-08` | 安全な障害確認を行う | `T-07` | `V-07`、`V-09`を確認し、未観測の障害を意図的にAtCoderへ起こさない |
| `T-09` | 方式Aの認証を検証する | `T-02`〜`T-04` | 主要導線とは別の実行で`V-10`、可能な範囲の`V-11`を追加提出なしで確認する |
| `T-10` | 成果物を確定する | `T-08`または`T-09` | 匿名化、合否判定、初期値候補、問い合わせ用事実、正本文書への反映候補を記録する |

`T-06`まではAtCoderへの提出を行いません。`T-06`で一つでも確認できない項目がある場合は停止し、提出回数を消費しません。`T-09`は主要導線と別の実行にでき、追加提出を行いません。

## 2. 検証入力

実行前に次を決め、成果物の「実行条件」へ記録します。

| 入力 | 選定条件 | 成果物へ残す内容 |
|---|---|---|
| 対象問題 | 終了済みの通常のAlgorithm過去問1件。対話的問題、特殊コンテスト、個別規則が不明な問題を避ける | 正規問題ID、公式URL、終了済みと確認した時刻 |
| 言語 | 正規言語IDを一つだけ選ぶ | 正規言語ID、提出直前に解決したAtCoder固有のID・表示名・処理系・バージョン |
| OS | 実機一つだけ | OS名、バージョン、CPUアーキテクチャ。ホスト名と利用者名は残さない |
| アカウント | 検証者自身が所有する一つのアカウント | 識別情報を取得できた事実と期待値との一致。不必要な場合は実際のユーザー名を残さない |
| ソースコード | 検証者自身が作成し、対象問題へ提出してよいもの | `source-A`等の実行内別名とバイト数。本文、ハッシュ、絶対パス、生出力は残さない |

提出IDは`V-04`と`V-06`が終わるまで一時領域で保持します。成果物では`submission-A`等の実行内別名へ置き換え、公開情報との恒久的な紐付けが必要だと別途判断した場合だけ実際のIDを残します。

## 3. 当日の外部条件

実行日の直前に、少なくとも次を再確認します。

- [AtCoder利用規約](https://atcoder.jp/tos?lang=ja)
- 対象コンテストの公式ルールと終了状態
- [AtCoderのAI学習拒否設定の説明](https://info.atcoder.jp/overview/about/ai-training-opt-out)
- [`online-judge-tools`の公式リポジトリ](https://github.com/online-judge-tools/oj)と[Cloudflare関連Issue](https://github.com/online-judge-tools/oj/issues/934)
- 使用するパッケージの公開版、取得元、ハッシュまたはGitリビジョン

確認したURL、確認時刻、確認結果だけを記録します。規約本文、問題文、Issue本文の複製は成果物へ含めません。

次の場合は検証を開始しません。

- 対象問題が終了済みか判断できない
- 個別規則と一般利用規約の関係を判断できない
- ログインにCAPTCHA、Turnstileその他のBot対策の回避が必要になる
- 他人のCookie、方式C・方式Aで許可していないbrowser Cookieの取得、プロキシ切り替え等が必要になる
- 1問だけにアクセスする構成、有限の待機、リクエスト数の計測を保証できない

## 4. 隔離した実行環境

### 4.1. 作業場所

検証用作業データは、`mktemp -d`等で作ったリポジトリ外の一時ディレクトリへ置きます。シェル変数には`ALGOLOOM_VERIFY_ROOT`等のタスク固有名を使い、`HOME`を上書きしません。

一時ディレクトリには所有者だけがアクセスできる権限を設定し、次を同じ配下へ分けます。

```text
<ALGOLOOM_VERIFY_ROOT>/
├── venv/          # 検証専用のPython仮想環境
├── work/          # 入出力例、提出用ソースコード、使い捨て検証コード
├── state/         # 専用Cookieファイル等の外部ツール状態
└── scratch/       # 成果物へ転記する前の一時出力
```

リポジトリ直下の`.verification-work/`も誤操作時の退避先としてGitの対象外にしています。ただし、認証情報は除外設定だけに頼らず、原則としてリポジトリ外へ置きます。

### 4.2. 方式Cの一時session取り込み

方式Cは、検証者本人が通常のbrowserでloginして得た`REVEL_SESSION`一つだけを、入力を表示しない対話promptから検証用clientへ一度だけ取り込みます。

- Cookie値をcommand line、`argv`、environment、shell history、clipboardを読む自動処理へ渡しません。
- browserのDeveloper Toolsから値をcopyするため、clipboardへ残り得ることを実行前に確認します。検証clientがclipboardの消去を保証したとは扱いません。
- Cookie名と送信先を固定し、他Cookie、他domain、他人のsessionを受け付けません。
- 一時directoryは作成時から`0700`、一時fileは作成時から`0600`相当にし、既存fileを追記または上書きしません。
- Cookie jarへ期限を追加せず、browserまたはserverが示した属性を観測値として扱います。
- 取り込み直後に`V-02`を実行し、account identityを確認できない場合はCookieを破棄して停止します。

方式Cは今回の技術検証だけの例外であり、製品用の認証fallback、CIまたは非対話実行として残しません。

#### macOS・Google ChromeでのV-04自己検証

V-04を自己検証する場合は、リポジトリルートの**ターミナル**で次を実行します。ブラウザのConsoleで実行するコマンドやJavaScriptはありません。

```console
python3 scripts/verification/atcoder_v04_verdict.py \
  --discover-state \
  --guided-chrome
```

`--guided-chrome`はGoogle Chromeで`https://atcoder.jp/settings`を明示的に開き、Safariや既定ブラウザへfallbackしません。V-03の空の専用Chromeプロファイルは終了時に削除済みのため、この方式Cの確認では通常のChromeプロファイルを使います。ログイン画面なら本人が通常ログインと必要なTurnstileを完了して`/settings`へ戻り、既に設定画面なら再ログインせず表示アカウントを確認します。別アカウントの場合は先へ進みません。

同じChromeで`⌥⌘I`を押し、`Application > Storage > Cookies > https://atcoder.jp`から、`Name=REVEL_SESSION`、`Domain=atcoder.jp`、`Path=/`の一意な行の`Value`セルだけを非表示ダイアログへ貼り付けます。スクリプトはChromeのCookie DBやクリップボードを自動読取せず、通常のChromeを終了・削除しません。状態ファイルの選択、結果の自動保存、0件・複数件時の停止を含む詳細は[検証支援スクリプトの説明](../../../scripts/verification/README.md#atcoder_v04_verdictpy)を参照します。

#### V-03直後からV-04を観測する統合再検証

既存の最終判定済み提出から判定待ちは復元できません。V-04を再検証する場合は、方式Cの本人照合を提出前に済ませ、V-03で提出IDを取得した直後からV-04を開始する[`atcoder_v04_integrated.py`](../../../scripts/verification/atcoder_v04_integrated.py)を使用します。

この統合スクリプトは新しい提出を1件行います。[`p0-21`](results/2026-08-12-p0-21.md)で提出上限を明示承認済み実サービス検証実行ごとに最大1件へ変更し、V-03→V-04統合再検証の新規提出最大1件を許可しました。その許可は[`p0-22`](results/2026-08-12-p0-22.md)の実サービス実行で消費済みです。新たな明示承認なしに再実行しません。許可は日単位で自動更新されず、`SEND_STARTED`相当以降は成功・失敗・応答不明のいずれでも消費し、同じ許可で再提出しません。コマンド、3フェーズの手動操作、安全境界は[統合スクリプトの説明](../../../scripts/verification/README.md#atcoder_v04_integratedpy)を正とします。

統合実行では、通常ChromeでV-04方式Cセッションを準備した後、別の空の専用ChromeでV-03を人が操作します。V-03一時状態の作成をローカルで検出すると、V-03プロセスの後始末完了を待たず、同じ提出ID1件のV-04有限ポーリングを開始します。Cookie取得、本人照合、拡張読込、ログイン、エディタ往復、Turnstile、承認句、最後の提出ボタンを番号付きで案内し、提出ID取得後のV-04には追加の手動操作を挟みません。

### 4.3. ツールの固定

システムのPython環境へ直接インストールせず、検証専用の仮想環境を使います。実行時には次を記録します。

- Python、`uv`、`online-judge-tools`、`online-judge-api-client`と直接利用するHTTPライブラリのバージョン
- PyPI版なら配布ファイルのバージョンとハッシュ、Git版ならリビジョン
- パッケージ解決結果
- 実行した入口が`oj`、`oj-api`、Python API、使い捨ての薄いラッパーのどれか

`online-judge-tools`のCLIと`online-judge-api-client`の構造化出力は別々に評価します。CLI全体が動作しても、提出ID、アカウント識別情報、判定観測を安定した型で取得できなければ、`JudgeAdapter`の候補実装として無条件に採用しません。

起動時の自動更新確認等、AtCoder以外への通信もリクエスト集計と混同しないよう、送信先別に記録します。

提出一覧を反復する下位APIを使う場合、ページを一つに明示的に制限し、対象の提出IDを見つけた時点で停止します。既定の反復処理へ無制限のページ列を渡さず、過去の提出全体を取得しません。提出IDを指定して一件だけ取得する経路を実証できるかも、`V-04`と`V-06`の採否根拠へ含めます。

### 4.4. 再利用可能な検証支援コード

再検証と将来の実装判断に役立つコードは、次をすべて満たす場合に[`scripts/verification/`](../../../scripts/verification/)へ保持できます。

- Cookie、トークン、パスワード、実際のアカウント名、提出用ソースコード、入出力例の実値、生の応答を含まない。
- 認証情報を引数、環境変数、設定ファイルへ置かず、必要な場合は表示しない対話入力で受け取る。
- 送信先、HTTPメソッド、リクエスト数、間隔、タイムアウト、リダイレクト、再試行、外部作用をコードレビューで確認できる。
- ローカルテストが実サービスへ接続せず、入力検査と分類を固定入力で確認できる。
- 実行時の仮想環境、Cookie、一時JSON、生ログをリポジトリ外へ置き、成果物確定後に破棄できる。
- 製品コード、通常の認証導線、CI用の認証手段、実サービスでの合格証拠として扱わない。

保持する版が、過去に削除した使い捨てファイルを実行記録から再構成したものである場合は、バイト単位で同一と表示しません。観測事実は引き続き`results/`の実行記録を正とします。

## 5. 観測と保存の境界

### 5.1. 記録するもの

- UTCの取得時刻と単調増加時計で測った処理時間
- 操作の入口、終了コード、成功・失敗・状態不明の分類
- 許可リストへ正規化したフィールド名、型、単位、欠損
- HTTPメソッド、送信先の分類、応答状態の分類、リクエスト数、待機時間
- 入出力例の件数と入力・期待出力の対応関係を確認できた事実
- 言語候補数と、一意に解決したID、表示名、処理系、バージョン
- 判定待ちと最終判定の時刻付き観測

### 5.2. 記録しないもの

- Cookie、パスワード、セッショントークン、CSRFトークン、認証用URL
- `Authorization`、`Cookie`、`Set-Cookie`を含む生のHTTPヘッダー
- 問題文、生のHTML、完全なJSON応答、入出力例の実値
- 提出用ソースコード、標準入力、標準出力、標準エラー出力
- 実際のアカウント名、メールアドレス、ホスト名、利用者名、不要な絶対パス
- 外部ツールの生ログ、例外の完全なスタックトレース

`oj-api get-problem --full`のように必要な言語一覧と保存禁止の生HTMLを同じ応答へ含める入口を使う場合、応答全体をファイルへ保存しません。処理中に許可したフィールドだけへ射影し、射影後の値だけを観測記録へ転記します。

## 6. 実行ゲート

### 6.1. 読み取りゲート

次の順に実行し、各操作の間隔とリクエスト数を記録します。

1. 方式Cで本人の`REVEL_SESSION`だけを一時的に取り込み、提出せずに認証状態とアカウント識別情報を確認する（`V-02`）。
2. 同じ対象問題から公開入出力例だけを取得し、件数と対応関係を確認する（`V-01`）。
3. 対象コンテストで有効な言語一覧から、正規言語IDを一意に解決する（`V-05`）。

次のいずれかに該当したら提出へ進みません。

- アカウント識別情報を取得できない、または期待したアカウントと異なる
- ページ構造の変化と未認証を区別できない
- 入出力例の件数または対応関係を維持できない
- 言語候補が0件または複数件になる
- Adapterの通信でchallenge、429応答または外部サービスの拒否を観測した。通常browserで利用者がTurnstileを手動操作した事実だけでは停止しない
- 提出後に提出IDを構造化して取り出す経路が事前の静的確認で見つからない

`V-02`は次をすべて満たした場合だけ合格とします。

- 空のsessionによる認証必須pageへのrequestが、login pageへの許可されたredirectとして未認証に分類される。
- 方式Cのsessionによる同じrequestが成功し、許可list化した構造からaccount identityを一意に取得できる。
- 取得したidentityが、事前に固定した期待値と完全一致する。
- 200応答でもidentityを解釈できない状態を、認証済みではなくpage構造変更として区別する。
- Cookie値、生header、生HTMLを成果物または通常logへ残していない。

### 6.2. 提出ゲート

AtCoderへ送信する直前に、実行者が次を一画面で確認します。

- 正規問題IDと公式URL
- 取得済みアカウント識別情報が期待値と一致したこと
- 正規言語ID、AtCoder固有の言語ID、表示名、処理系、バージョン
- ソースコードのバイト数とハッシュ。成果物には値を残さない
- この操作が、目的と対象を事前記録して明示承認された実サービス検証実行の最大1件であること
- AtCoderのAI学習拒否設定を必要に応じて確認する公式リンク
- 送信開始後に応答が不明でも自動再送しないこと

この確認に対する明示的な承認後だけ`V-03`を実行します。確認を省略する非対話オプションや、提出前待機を無効化するオプションは使用しません。`SEND_STARTED`相当以降は結果が不明でも提出枠を消費し、同じ承認で再提出しません。日付の変更は新しい提出許可になりません。

### 6.3. 提出後

1. 応答から提出IDを取得し、`submission-A`として一時的に関連付けます（`V-03`）。
2. 同じIDだけを使い、判定待ちと最終判定を取得時刻付きで観測します（`V-04`）。
3. 最初のプロセスを終了し、別プロセスから同じIDを再照合します。再提出を呼ぶ経路は使いません（`V-06`）。
4. 返された場合だけジャッジ実行時間とメモリを単位付きで記録し、欠損時は欠損のままにします（`V-08`）。

ポーリングの上限へ達しても提出失敗とは判定しません。提出IDを保持したまま`VERDICT_PENDING`相当として終了し、後から同じIDで再確認します。

### 6.4. 方式Aの認証gate

方式Aの`V-10`は、方式Cによる主要導線と別の実行記録にします。追加提出は行わず、次を順に確認します。

1. 既存browser profileとは異なる、空の専用profileのpathを作成する。
2. Cloudflare保護ページをリモート制御状態にせず、可視browserを起動する。CDPのpipeまたはportをログイン中に使用しない。
3. 検証者がusername、password、Turnstileをbrowser上で手動操作する。
4. login完了後、`p0-23`で安全性とCloudflare互換性を確認した検証境界から、helperが`https://atcoder.jp`の`REVEL_SESSION`だけを取得する。CDPへ自動的に戻さない。
5. 同じsessionで`V-02`と同じaccount identity確認を行う。
6. 期待値一致後だけ検証用secret storeへ保存し、processを再起動して同じidentityを確認する。
7. browserを終了し、一時profileと制御channelを後始末する。
8. Cookie、password、生header、既存profileのdataがlog、scratch、成果物へないことを検査する。

次のいずれかでは`V-10`を不合格または中止とし、回避策を追加しません。

- 可視の専用browserでも通常のloginを完了できない。
- headless化、fingerprint偽装、stealth設定、Turnstile自動操作が必要になる。
- 必要なCookieだけへ限定できない、または既存profileを参照する必要がある。
- account identityを一意に確認できない、または期待値と一致しない。
- debug channelをlocal child processへ限定できない。
- Cloudflare保護ページで`navigator.webdriver`が真になる、または公式互換性チェッカーのAutomation Checkに失敗する。
- Cookie値を成果物へ残さずに合否を説明できない。
- 異常終了時のbrowser processまたは一時profileを安全に回収できない。

`V-11`では通常操作中の`Set-Cookie`だけを観測し、session維持目的のbackground requestを送信しません。serverが返さないexpiryを補わず、更新が観測されなかった場合もその事実を記録します。

## 7. 障害確認

障害の証拠を次の3段階に分けます。

| 証拠 | 意味 | 例 |
|---|---|---|
| 実サービスで観測 | 通常操作中にAtCoderから実際に得た事実 | 未認証、判定待ち、最終判定 |
| ローカルで制御 | AtCoderへ負荷を掛けず、使い捨て検証コードで起こした事実 | 接続失敗、応答遅延、待機指示、形式不正 |
| 静的確認 | 使用ライブラリの公開インターフェースや実装を確認した事実 | 接続とリクエストの上限を別々に指定できるか |

`V-07`と`V-09`のために、AtCoder側の拒否、レート制限、ページ変更、通信障害を意図的に発生させません。空の専用Cookieファイルによる未認証確認と、ローカルの制御可能なHTTP応答を優先します。実際に観測していない状態は、別の障害を根拠に「観測済み」としません。

期限切れセッションを確認するために、使用中のブラウザセッションを複製または破壊しません。安全に用意できない場合は未観測とし、どの例外や応答を分類境界にする予定かを静的確認として分けて記録します。
